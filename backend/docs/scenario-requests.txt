FORTIFY - SAMPLE REQUESTS FOR 10 FRAUD SCENARIOS (100 requests)
==================================================================

All customers, sessions, accounts, names and phone numbers below are FICTIONAL and come from the
scenario seed (data/seed/scenarios.json and data/seed/scenario-samples.json, from scripts/gen-scenarios.py).

How to send (replace <key> only if 'Require API key' is on in Admin & Settings -> API Configuration):
  curl -X POST http://localhost:3000<endpoint> -H 'Content-Type: application/json' -H 'X-API-Key: <key>' -d '<json>'

Expected decisions were verified by running all 100 requests as a dry run through the default
workflows (Default Transaction / Login / Account Update Scoring). Decisions for transfers:
  ALLOW = completed | HOLD = held for an analyst | CHALLENGE = OTP sent to the customer | DECLINE = cancelled
Decisions for login / account update: ALLOW | CHALLENGE (step-up) | DENY

Notes
- Signals such as screen sharing, VPN, rooted / new device, copy-paste and failed PINs come from the
  SESSION record on the server (sessionId), not from the request body. That is why each transfer uses
  its own scenario session.
- Sending a request for real saves the transaction / event, raises alerts and logs customer messages
  (Risk Intelligence -> Customer messages). Use the workflow 'Try (dry run)' to test without saving.
- Results depend on the active rules and settings; dependencies are listed per scenario.
